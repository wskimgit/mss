# MSS 원형 보호 계약 v1.0 — 동결

## 1. 원형 기준본

MSS 원형 기준본은 다음 하나뿐이다.

- 경로: master/MSS_MASTER_v6.2.1_FROZEN_CURRENT.md
- Git blob SHA: e127a821682b30d6661b20d40f80314a5d2f2bde

실행 전에 반드시 실제 파일 해시가 위 값과 일치하는지 확인한다.
불일치하면 MSS 실행을 중단하고 원형 훼손으로 판정한다.

## 2. 원형 불변 영역

다음은 하위규칙, 검증계약, 자동개선, 버전업으로 변경할 수 없다.

- 사실 경계
- 생성형 인공지능 최종판단 최고권위
- 최종 목적
- 신규발굴 원칙
- 이전 추천 자동우선권 금지
- 사용자 표시언어 한글
- 출력 8개 구역
- 마지막 결론 블록
- 공식 실행의 기본 의미

원형을 바꾸려면 사용자가 원형 변경을 명시적으로 지시해야 한다.

## 3. 하위규칙의 권한 제한

하위 검증규칙은 다음만 할 수 있다.

- 자료무결성 검사
- 최신성 검사
- 단계 정합성 검사
- 실행자산 일치 검사
- 재현성 검사
- 오류 검출
- 내부 실행 최적화

하위규칙은 다음을 할 수 없다.

- 원형 목적 변경
- 최고권위 변경
- 출력 구역 삭제·추가·순서변경
- 출력 제목 변경
- 결론 제목 변경
- 결론 줄수 변경
- 사용자 상태용어 변경
- 공식 실행을 다른 지시문으로 대체
- 원형 마스터를 연결문서나 요약문으로 대체

충돌 시 원형이 항상 우선한다.

## 4. 출력 원형 — 절대 고정

사용자 출력은 반드시 다음 8개 구역을 그대로 사용한다.

1. 머리말
2. 시장 및 주도력
3. 시장탐색 압축경로
4. 상위 후보
5. 사용 근거
6. 생성형 인공지능 최종판단 및 신뢰도
7. 자료 무결성
8. 생성형 인공지능 자가검증 및 지시문 개선

마지막 결론은 반드시 다음 제목과 4개 줄을 사용한다.

MSS 한줄 결론
│ 최우선: [종목/없음]
│ 다음 후보: [종목들/없음]
│ 신뢰도: [높음/중상/중간/중하/낮음]
│ 핵심: [가장 중요한 한 문장]

마지막 "│ 핵심:" 줄 뒤에는 어떠한 문장도 출력하지 않는다.

## 5. 반복실행 변형 금지

매 실행은 지시문을 다시 작성하지 않는다.
매 실행은 지시문을 해석해 수행만 한다.

자가검증은 결과와 실행구조를 검사한다.
자가검증 결과만으로 원형 본문을 자동 수정하지 않는다.

구조적 문제가 발견되면:
문제기록
→ 원인분석
→ 하위 검증계약 개선안 작성
→ 회귀검증
→ 사용자 요구가 원형 변경을 명시하지 않은 한 원형은 그대로 유지

## 6. 상속 규칙

필수 상속 순서:
원형 기준본
→ 원형 보호 계약
→ 하위 검증계약
→ 실행자산

하위계약은 원형을 상속하며 원형을 침범할 수 없다.
상위 원칙을 하위 규칙이 재정의하면 그 하위 조항만 무효다.

## 7. 실행 전 강제검사

- 원형 파일 해시 일치
- 원형 8개 출력구역 존재
- "MSS 한줄 결론" 존재
- 공식 실행 절 존재
- 하위계약이 원형 출력형식을 재정의하지 않는지 확인

하나라도 실패하면 실행하지 않는다.
